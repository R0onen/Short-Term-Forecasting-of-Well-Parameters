# Стратегия прогнозирования

## Цель и момент выпуска

Обязательная цель — `pump_fillage` семи скважин `sucker_rod_pump`. Для каждой пары скважина–горизонт (h = 1, …, 24) обучается отдельный Ridge. Всего до 168 небольших моделей. Такой объём сохраняет индивидуальную динамику скважин и позволяет вычислять все горизонты напрямую, без передачи одного предсказания в следующий шаг. Целевое значение — опубликованное часовое среднее в процентах. Обоснование и покрытие — в [DATASET_ANALYSIS.md](DATASET_ANALYSIS.md#выбор-цели).

`origin_ts = t` — метка начала последнего доступного часового интервала `[t, t+1 ч)`. Момент выпуска — `t+1 ч`. Метка цели `target_ts = t+h` обозначает начало целевого часа. Факт `y[t+h]` становится доступен в `t+h+1 ч`, ровно через `h` часов после выпуска. Представление меток определено в [INTERFACES.md](INTERFACES.md#time-types-and-missing-values). Набор не сообщает задержку поступления. Для backtest предполагается, что завершившийся агрегат доступен к моменту выпуска. История в пределах `test` раскрывается последовательно. Параметры модели после окончания `train` фиксируются.

## Признаки и модели

| Метод | Предсказание для часа (t+h) | Условие выпуска |
| --- | --- | --- |
| Naive | `y[t]` | Есть значение цели в текущем завершившемся часу. |
| Seasonal naive, период 24 ч | `y[t+h−24]` | Есть значение для того же часа предыдущих суток относительно цели. При `h = 1` источник — `y[t−23]`, при `h = 24` — `y[t]`, как у naive. |
| Ridge | Лаги цели в часах `0, 1, 2, 3, 6, 12, 24` относительно `t` и синус/косинус часа суток `t+h` | Есть все нужные значения. Час цели заранее известен из календаря. |

Сначала создать полную часовую сетку для каждой скважины, затем строить лаги и сдвиг целевой метки внутри скважины. Каждый метод проверяет свои входы независимо. При отсутствии нужного лага метод пропускает этот выпуск. Пропуски, маски и значения цели вне [0, 100] не заполняются. Fit требует все признаки и известную метку. Прогноз использует только допустимые лаги и календарь. Факт из будущего присоединяется после вычисления прогноза и нужен для оценки. Нули `pump_fillage` сохраняются. Флаги других датчиков не переносятся на цель. `dynamometer_area` остаётся в аудите и не используется в моделях. Для NK-7 обучающие примеры Ridge и их исторические признаки целиком берутся с 2026-06-01. Граница задана по карточке и проверке смены режима, фиксируется до оценки. [Описание аномалий в датасете](DATASET_ANALYSIS.md#проверенные-аномалии-и-решение-для-пайплайна).

Ridge применяется через `Pipeline` с `StandardScaler`. Одна `alpha` из `0.1, 1.0, 10.0` выбирается для всех скважин и горизонтов по среднему MAE групп на внутренней валидации. Каждая группа скважина–горизонт получает равный вес. Для всех кандидатов используется один набор валидационных точек. При равенстве брать 1.0, если он среди лучших, иначе меньшее из лучших значений. Общий выбор ограничивает время на подбор и число решений. Для всех выпусков Ridge ограничить предсказание диапазоном [0, 100] до расчёта MAE и сохранения. Оба baseline уже лежат в этом диапазоне. [Ridge в scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html).

## Хронологический протокол

1. Задать внутреннюю границу `V = 2026-07-15 00:00` внутри официального `train`. Для fit брать строки с `target_ts < V` и признаками, доступными к `origin_ts`. Валидационные цели — `V <= target_ts < test_start`, валидационные выпуски — с `V − 1 ч`. Последний обучающий агрегат доступен при завершении этого часа. Для каждого кандидата scaler обучается на внутренних обучающих строках соответствующей скважины и горизонта. Валидация использует наблюдавшуюся к каждому выпуску историю `train` без обновления scaler или Ridge.
2. После выбора `alpha` переобучить каждую модель и её scaler на подходящих строках с `target_ts < 2026-08-08 23:00`. Цели, пересекающие официальную границу, исключаются из fit. Для NK-7 применить границу режима также к лагам.
3. На официальном `test` пройти по выпускам в порядке времени начиная с `origin_ts = 2026-08-08 22:00`. Выпуск для этого часа делается после его закрытия, когда доступны все обучающие цели. Требовать `target_ts` внутри `test`. Использовать значения до `origin_ts` включительно из `train` или уже наблюдавшейся части `test`. Первые `h − 1` часов `test` для горизонта `h` лежат раньше первой допустимой цели. У всех методов одна граница выпусков. `y_true` присоединяется только для расчёта ошибки.
4. После оценки сохранить один 24-часовой выпуск на скважину с последнего `t` на или после первого допустимого выпуска, для которого есть нужные значения всех трёх методов на горизонтах 1–24. Это требует всех значений с `t − 24 ч` по `t`. Модели и scaler те же, что в backtest. Дашборд показывает время выпуска и его давность относительно конца архива. Если выпуск старше последнего часа, часть или весь диапазон прогноза может лежать внутри архива. Траектория не участвует в расчёте MAE. На опубликованной сетке последнее такое окно для NK-91 заканчивается 29 сентября в 09:00, для остальных шести — 30 сентября в 23:00. При отсутствии окна интерфейс объясняет причину.

## Недостаточные данные и диагностика

На официальной ревизии каждая из 168 пар скважина–горизонт должна иметь хотя бы один допустимый пример внутреннего fit, одну допустимую точку валидации и хотя бы один пример финального fit. При пустой группе, ошибке обучения или нечисловом результате остановить прогон до публикации и указать этап, скважину, горизонт и число пригодных строк. Сохранять прежние результаты. При корректном fit и пустом пересечении test сохранить три строки метрик с `n_common=0` и `mae=NULL`. Отсутствие полного окна последнего выпуска даёт пустую траекторию для скважины.

В рамках M03 после A04 выполнить [диагностику NK-7 на 1 и 24 ч](INTERFACES.md#forecast-diagnostic-and-run-report), используя только train. По итогам диагностики исправить нарушения контракта и повторить проверку. Полный M03–M05 повторно выбирает alpha на всех группах и выполняет обязательный эксперимент на 7 скважинах, 24 горизонтах и 3 методах.

## Сравнение и отчёт

Для каждого `(well_id, parameter, horizon_h)` взять пересечение ключей `origin_ts, target_ts`, где доступны факт и все три предсказания. Для каждой модели MAE равна среднему `abs(y_true − y_pred)` на этом наборе в процентных пунктах. В отчёте сохраняются `n_common`, `n_actual` (все пригодные значения цели этого тестового периода для скважины) и доля `n_common/n_actual`. Для каждого горизонта число общих точек может отличаться. Сравнение моделей выполняется внутри горизонта. На дашборде рядом показываются MAE и покрытие. Сохранить JSON-отчёт полного прогона с версией данных и кода, окружением, конфигурацией, результатами внутренней валидации и выбранной alpha по [контракту отчёта](INTERFACES.md#forecast-diagnostic-and-run-report). В отчёте разобрать NK-7 отдельно и указать, где базовые методы выигрывают. Опциональный общий показатель по горизонту — среднее MAE по скважинам с доступной оценкой и явным числом скважин. [Формула MAE в scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.mean_absolute_error.html).

Обязательны семь скважин, 24 горизонта, три метода и описанная оценка. После сдачи обязательного объёма можно добавить `tubing_pressure`, проверить градиентный бустинг или оценить чувствительность к выбору режима NK-7 и правил заполнения коротких пропусков. Любой подбор расширений проводится внутри `train`.
