# Обзор проекта

**Short-Term Forecasting of Well Parameters** — финальный проект курса «AI Programming», кластер 4 «Industrial Sensor Data Analytics (NK Oil Wells)». Команда из трёх студентов строит воспроизводимый пайплайн от почасовых измерений до прогноза и защищает инженерные решения на фактических данных. Источник — [NK Oil Well Sensor Monitoring v2](https://huggingface.co/datasets/Arailym-tleubayeva/NK-Oil-Well-Sensor-Monitoring-v2).

**Задача ML.** В конце каждого доступного часа оценить `pump_fillage` через 1–24 часа для каждой из семи насосных скважин. Сравнить три метода на одних и тех же наблюдениях отдельно по скважине и горизонту. Результат сравнения определяется после оценки. Критерий сдачи — корректный протокол и воспроизводимые метрики.

| Требование | Что демонстрирует команда |
| --- | --- |
| A. Инженерия данных и SQL | Преобразование long → wide по ключу скважины, часа и параметра. Таблицы в SQLite, интервалы между измерениями через `LAG`, суточные и месячные агрегаты. |
| B. Аудит качества | Покрытие календаря, флаги, дубли и несогласованные измерения. Майский сдвиг `dynamometer_area` и режим NK-7 с июня. Исходные значения доступны, решения об исключении прослеживаются. |
| C. EDA | Описательные статистики, внутрисуточные профили, тренды, корреляции, сравнения скважин и типов с учётом единиц, пропусков и выбросов. |
| D. Визуализация | Пять содержательных интерактивных графиков. Фильтры скважины, параметра и периода. История, прогнозы, MAE и покрытие. |
| E. Машинное обучение | Naive, seasonal naive и Ridge на лагах. Исходные `train/test` без перемешивания, временная валидация внутри `train`, MAE по скважинам и 24 горизонтам. |

EDA и аудит охватывают оба типа скважин. По фонтанным скважинам интерфейс показывает историю давления и аудит. В согласованном объёме прогноз рассчитан для `pump_fillage`. `tubing_pressure` — кандидат для расширения, если потребуется прогноз по обоим типам.

Планируемый результат для сдачи — репозиторий с инструкцией воспроизведения, SQLite и SQL-запросами, отчётами аудита и оценки, локальным Streamlit и демонстрацией. Соответствие требований рабочим задачам приведено в [TEAM_TASKS.md](TEAM_TASKS.md#покрытие-требований).
