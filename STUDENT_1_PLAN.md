# Student 1 implementation plan — Data engineering, SQLite and audit

## 1. Project context

Short-Term Forecasting of Well Parameters is a three-person AI Programming project. NK Oil Well Sensor Monitoring v2 provides 258,387 hourly, long-format sensor records from 10 wells. Build the reproducible Python/Pandas and SQLite pipeline used by the forecasting and Streamlit modules. Own course requirement A and the data side of B. Student 2 owns the seven-well `pump_fillage` forecast. Student 3 owns analysis and visualization of both well types.

The official `train` contains 206,706 rows from 2026-01-01 00:00:00 through 2026-08-08 22:00:00. The official `test` contains 51,681 rows from 2026-08-08 23:00:00 through 2026-09-30 23:00:00. Keep the source partitions. Download the two inputs from Hugging Face revision `4004bb78ca8811a87c2892a89e457c59d22ace2b`. The combined CSV is redundant. [Pinned dataset files](https://huggingface.co/datasets/Arailym-tleubayeva/NK-Oil-Well-Sensor-Monitoring-v2/tree/4004bb78ca8811a87c2892a89e457c59d22ace2b).

## 3. Step-by-step development instructions

After implementation approval, work on A01 and collect both consumer reviews. Start A02 after [SHARED CONTRACT READY](INTERFACES.md#shared-contract-ready).
1. **A01.** Confirm one Python version, with 3.12 as the proposed baseline. Pin compatible versions of Pandas, NumPy, scikit-learn, Plotly, Streamlit and pytest in `requirements.txt`. Use the standard `sqlite3`. Confirm window-function support on the supported Python runtime. Put all table definitions in `schema.sql`, including initially empty result tables. Enforce keys and sensible domain constraints such as split, booleans, model IDs and horizon range. Index `measurements_long(well_id, parameter, timestamp)`. Enable foreign keys before transactions, load wide before long, and verify the schema against the canonical PKs, FKs and NULL constraints. Record the exact installed dependency versions and actual Python and SQLite versions for the A01 review. Seed valid and missing hours, a flagged measurement, a zero, an absent applicable series and a structurally inapplicable series. Include a small known result example and enough uninterrupted hours on both sides of a fixture cutoff for lag-24 tests. Use test time bounds supplied by callers. In the fixture, use known valid metadata bounds for both train and test, reserve enough train history for the inner validation cutoff, and include a viable well/horizon for the 24-hour release. Keep official-source checks enabled for normal runs.
2. **A02.** Fetch `train.csv` and `test.csv` from the pinned revision using their Hugging Face `resolve/<revision>/<filename>` paths. Compare SHA-256 before accepting a download or cached input. Train hash is `8bf92fd97ac9b0d7ec2e7aa61be90f335c7f3b6ab2a84634fb8758b057efe26a`. Test hash is `8029113613ea2965cb94fc7bea50eee6f4c327b673ecc856d88d25dfb652c7d6`. Check the exact header and valid row counts and time bounds. Keep original field text, split and source record number, including rows that fail semantic validation. Surface a structural parsing or manifest failure and leave the existing DB in place. Use synthetic rows to exercise validation without changing the official manifest. For the integration fixture keep at least one target series with enough history to provide complete lag windows and known targets at all 24 horizons in both internal fit and validation, and a complete latest release window. Put deliberate gaps outside those required windows or on other series.
3. **A03.** Validate hourly timestamp format and split membership, expected well and parameter, well type and unit, finite value and positive integral `n_obs`. Preserve bad rows in raw and record why they do not enter long. For an exact duplicate of validated content retain one deterministic representative and log repeats. For a conflicting observation key, log each involved raw row and leave the key absent from long. Parse semicolon-separated flags while preserving their original text. For a validated flagged record, retain `value` and set `is_usable=0` only for that parameter. Tally distinct flagged rows as well as individual codes. The observed codes are `weight_overflow`, `area_negative`, `area_extreme`, and `spm_outlier`. Flag and mask both sides of each reversed rod-load pair. Mask out-of-range `pump_fillage`. Preserve legitimate zeros. Record period events as `area_scale_shift` and `nk7_regime_change`, with `action=annotate`. Mark the May window for each pump well and include the documented May 8 NK-82 detail. Mark the NK-7 regime beginning 2026-06-01, with enough per-parameter context for SPM, area and fillage views. Calculate source-value medians before and after, clearly labeling periods. Record the scale shift and regime without applying a unit correction. Cross-check the 7,041 flagged rows and the 13 reversed pairs against the pinned files.
4. **A04.** Freeze catalog applicability from the published archive. The fountain wells are NK-75, NK-76 and NK-83. Each has tubing and line pressure in atm. NK-75 and NK-83 also have casing pressure in atm. NK-7, NK-68, NK-77, NK-82, NK-86, NK-91 and NK-93 have SPM in strokes/min, pump fillage in %, min/max rod weight in kg and dynamometer area labeled unitless. Pivot only usable numeric values by `(well_id,timestamp)` and `parameter`. Reindex to all eight sensor columns and the product of 10 wells and 6,552 expected hours. Derive the well type and split from the catalog and official hour bounds even on empty hours. Load every table using canonical DDL. Populate a temporary DB beside the destination, validate counts, key uniqueness and round trips, then close and replace the destination after success with Streamlit stopped and no competing writer. A rebuild initializes empty forecast result tables. Run the forecast command again before reopening the application.
5. **A05.** In `gaps.sql` apply `LAG` to observed long rows partitioned by well and parameter and ordered by time. Count flagged hours as observed. For well-wide outages first select distinct well-hours and partition by well. Return both bounding observations and the integer count of interior missing hours. Apply user date filters to overlapping gaps after establishing predecessors. Separately calculate expected, observed, usable and flagged counts with catalog × wide calendar and a left join to long. For `aggregates.sql` group by well, parameter and day or month, honoring the selected range, and compute counts, min, max and arithmetic mean of hourly values. Apply the analysis mode only to the values used in those statistics. Keep the observed and usable denominators available in both modes. Preserve a zero-observation bucket with NULL mean. Document that a partial bucket's denominator is the selected hours, and that pooling unlike units is invalid.
6. **A06–A08.** Start pivot tests while SQL is being completed. Test the full data contract, then run the same approved build and consumer entry points in integration. In the README describe input provenance, the exact run order, the effect of a rebuild, SQL examples and what a quality mask means. For defense show one source hour before and after pivot, a LAG gap, both anomalies and the difference between missing and masked values.

## 6. Testing

### Synthetic fixture and component checks

- Run `python -m pytest tests/test_data.py`. Build from schema and seed, check `PRAGMA table_info`, `foreign_key_list`, `integrity_check` and `foreign_key_check`. Attempt a validly typed child row with a missing parent and require rejection. Test malformed fields and split membership, exact versus conflicting duplicates, combined flags, raw provenance, masks, zeros, unit and catalog validation, and preservation of other sensors in a flagged hour. Compare wide values with the long mask and verify a failed build preserves the destination.
- Seed 00:00, 01:00 and 04:00 and verify a 3-hour delta and two missing hours. Verify no interior gap before the first observed hour. Add a trailing gap and a totally empty applicable series to test coverage. Verify counts and mean for values 0 and 10 within 24 hours, and verify clean-mode mean changes after masking a value. Include a partial calendar bucket and a selection clipping a gap.

- For the pinned data verify 258,387 raw rows, 43 catalog pairs, 65,520 wide rows, 83 globally absent hours, the 313 missing NK-86 hours at well grain and all 1,273 test hours absent for NK-75 line pressure. Verify NK-76 casing pressure is structurally inapplicable. Cross-check these acceptance counts against [DATASET_ANALYSIS.md](DATASET_ANALYSIS.md).
- After consumer checks run `python -m pytest tests/test_integration.py` and `python -m pytest`. Use temporary paths. Exercise the data assembly core and forecast runner on the fixture and read the resulting DB through the UI query layer. Then run the official command chain in a clean environment twice.
